0. 요약

  • 고객 이용 흐름

    • 매체 앱 진입 → 쇼핑플러스 목록·상세 → 쇼핑몰 이동 → 구매

    • 구매 → 취소·확정 반영 → 포인트 지급(익월 ‘말일’)

  • 운영 담당자 역할

    • 계약조건 및 매체 담당자 인수

    • ‘디벨로퍼’ 내 매체 등록·설정 및 캠페인 생성·연결·설정

    • API·지급 배치 등 개발 연동 협의

    • 프론트 연동, 지급 API·접속정보 협의 및 테스트 요청

    • 일정 조율, 결과 취합, 이슈 전달, 라이브·정산 확인

  • 매체별 진행 기록

    • 위키 내 계약조건·담당자·코드·명세 버전·일정 관리

    • 설정 완료·테스트 통과·실제 공개·첫 지급 완료 상태 구분

1. 계약인계

  • 오픈 일정 확인

  • 지급 방식: 일반 / 플러스콘 (쿠팡 포함 유무)

  • 매체 수수료 및 계약 조건 확인 (제외 광고주 포함)

  • 고객 적립률 확인 (미확정시 100% 지급 세팅)

  • 체결 계약서, 최종 협의 내용, 희망 오픈일, 운영/개발/정산 담당자 컨택포인트

구분

기준

일반 버전

갑(제휴사/매체)–을(핀크럭스), 매체 적립 책임 반영

플러스콘

회사(핀크럭스)–제휴사(매체), 포인트·쿠폰·유효기간 책임 반영

보안약정서

usrkey·ADID 등을 개인정보로 판단하거나 위수탁이 곤란한 경우 검토

부속계약서

광고주별 요율·정산·종료/변경 고지 규칙 명시

2. 매체 등록

  • 매체 등록 후 이커머스 설정 → 이커머스 매체별 설정

    • ADVID로만 검증, 리워드 정률 사용, 최대 리워드 지급 포인트 설정

    • 공용/개별 배치: 배치 형태/시간에 따른 분기 (개발팀 확인)

    • 헤더/플러스콘 사용 여부

    • 웹뷰 사용 여부: 가급적 웹뷰 사용으로 제안

  • 이용안내 등록: 지급 재화, 포인트 명칭 등 확인 반영

  • 포스트백 등록: 인벤토리에 세팅

  • 매체 연동 현황에 신규 매체 추가

이슈 케이스

  • CPA 타입으로 등록, 이커머스 설정 누락 → 쇼핑플러스 적용 타입(이커머스 설정)

  • POSTBACK 타입 설정: 매체에 따라 요구사항이 다른 경우 체크

  • 매체 제공 계정 내 메뉴 권한 노출 설정

사례 참고: SBI 테스트 실패 · SK증권 · KB Pay 코드 발급 협의 · 관리 메뉴 미노출

3. 캠페인 세팅

  • 매체 코드 발급 후, 연동자료 전달 전 캠페인 기본 설정 → 개발팀 샘플 URL 요청 해 노출 여부 확인

  • 오픈 광고주, 고객 적립률 확인

  • (필요시) 광고주/네트워크 담당자에게 코드 발급 요청

  • 메뉴 경로: 쇼핑플러스 → 쇼핑플러스 캠페인별 설정

  • 매체별 노출 대상·순서·적립 조건 등록,

  • 브랜드·포인트명·혜택·유의사항·이미지·다크모드 확인

  • 고객 적립률 미확정 시 고정된 매체 수익률의 100%로 임시 세팅

  • 최초 구매·한도·제외 상품·취소 조건·예정/확정 문구 확인

  • 구형/신형 UI 각각 신규 광고주 정보 확인

테스트 계정 한정 노출 (필요시) - LS증권 사례 참조

    • 사용자키 예외 노출 등 가능한 제한 방식 적용

    • 테스트 계정 노출 및 일반 고객 미노출 확인

4. 연동자료 전달

  • 고객 적립률 협의 현황·지급 방식, 매체·캠페인 코드, 테스트 진입 URL 전달

  • PUBKEY 확정 전달

  • 지급 연동 등 출발지 IP

    • 적립(운영) : 13.125.159.103, 15.164.71.152, 3.34.75.246

    • 적립(개발) : 52.79.92.213

  • 암호화 Key/IV (개발팀 발행 요청)

  • 광고주별 제약 사항

  • 광고주 계정, 디벨로퍼 전달

핀크럭스_쇼핑플러스 연동문서

핀크럭스_회원 동의 철회 연동문서_V2

광고주별 제약사항(위키)

광고주별 예상 매출 시나리오(위키)

회신 요청

  • 사용자 식별 방식(usrkey 생성 방식), 담당자, 첫 테스트 목표일 명시
  • 앱 브릿지(외부링크, 뒤로가기등) 스크립트
  • 철회 등 출발지 IP (화이트리스트 등록)

이슈 케이스

  • 공용 연동과 실제 연동 방식 차이

  • POST/GET·JSON/FormData·필드명·응답코드

  • 사설 IP·VPN 주소 수령 시 실제 외부 출발지 공인 IP 재요청

  • 다중 IP: 실제 주소 목록 전체 전달 및 등록 결과 확인

5. 프론트 연동

  • 테스트 앱 제공일·배포 버전·앱 심사 일정 수령

  • 진입 위치·버튼·서비스명·포인트 명칭·색상·로고 확정

  • usrkey 생성·전달방식 확인 (GET/POST 방식 포함)

  • ADID(쿠팡) 수집 여부

  • 진입 명세 확인

    • 매체 첫 오픈시 개발 환경 쓰지 않고 바로 ‘운영’ 환경에서 테스트 (개발환경 세팅이 필수인 경우 에 test-theapi

  • dt, us 등 매체별 적용 파라미터 확정

  • 암호화 대상·인코딩 순서·시간 제한·오류 응답 확인

  • 플러스콘 협의 및 세팅

  • 철회 연동 시 출발지 IP 확인 및 개발 세팅 (별도 추가 연동 시) (매체 → 핀크럭스)

체크리스트

  • OS별 매체 앱 → 목록 → 상세 → 광고주 앱/브라우저 → 복귀
  • 뒤로가기·닫기·앱 복귀 동작 확인
  • 다른 매체의 로고·포인트 명칭·안내문 잔존 여부 확인

이슈 케이스

  • 요청하신 페이지가 원활하지 않습니다.

    • dt 파라메터 urlencode 확인

    • us 파라메터 확인 : urlsafe 해서 넘겨주는 케이스 확인

  • 암호화 규격에 timestamp 추가 요청 케이스 있음 (timestamp+랜덤 3자리)

  • 회원 동기화가 선행 되어야 하는 케이스

  • 쇼핑플러스 자체를 웹브라우저로 이동시켜 뒤로가기가 불가한 케이스

  • 타 서비스 브랜딩 노출: 매체별 화면 설정 미반영으로 기본 브랜딩 잔존 → 로고·서비스명·포인트 명칭 등 매체별 화면 설정 수정

사례 참고: 키움증권 · 부산은행 · KT 엠모바일 · 국민은행 스타뱅킹 · LS증권 · 기본 브랜딩 잔존

6. 지급 연동

  • URL·POST/GET·JSON/FormData·필드명·자료형 확인

  • POSTBACK URL / IP 확인 (핀크럭스 → 매체)

  • 공통 배치 / 개별 배치 확인 (배치 시간)

  • 타임아웃, 미적립 시 처리 협의 (담당자 확인)

  • S2S 서버 암호화 필요 확인 (일반적으로 하지 않음)

  • 테스트 요청 및 적립 확인

  • 지급 배치 익월 말 세팅 및 모니터링

이슈 케이스

  • POST 요청시 HMAC 서명 (국민은행, 버즈빌 케이스)

  • 핀크럭스가 전송한 시간과 매체가 실제 지급처리 하는 시간의 차이 발생 (쇼플 UI에서는 지급으로 표시 됨)

사례 참고: 국민은행 스타뱅킹 · 부산은행 · KB Pay · 교보라이프플래닛 · SBI 배치 확장 · 지급 중계 설정 변경

7. 통합 테스트

구매부터 지급까지 통합 테스트 진행

  • 고객 적립률 확정·캠페인 노출 순서 등 확인
  • 매체앱 진입 OS별 동작, 외부 랜딩, 뒤로가기 등 스크립트 동작
  • 적립 예정 내역 정상 기록 여부 (구매, 취소)
  • 1원 지급 테스트: 실제 매체 지급 테스트

운영 전환 및 라이브

  • 오픈 일정 협의
  • 양사 운영 환경 최종 확인
  • 내부 세팅 최종 확인 (이커머스설정, 포스트백, 지급 경로)
  • 배치 활성화 (개발팀 세팅)
  • 최종 실적 발생 확인

이슈 케이스

  • 특정 유저(특히 담당자) 실적 누락: 유저키, 외부링크, CPS 코드(광고주) 확인 순

  • 광고주별 포스트백 시기 이슈로 미발생 케이스 문의

  • 개발앱/운영앱의 API조합 불일치 (개발앱에서 핀크럭스 운영 URL 세팅 불가)

  • 매체 배포시 ‘앱 배포’, ‘웹 지면 배포’ 차이에 따른 공개일 미확정 케이스

사례 참고: SBI저축은행 · 우리투자증권 배치 변경 · 중지 이력 · 부산은행 · 국민은행 스타뱅킹 · 일부 단말 구매 미노출 기록

9. 첫 지급 /정산

  • 첫 지급 전 집계 확인

  • 첫 배치 실행 확인

  • 정산 담당자와 정산 자료 교환(산출 근거, 디벨로퍼 참조)

  • 매체 AR: 키움증권 · KB Pay · KT 엠모바일 · LS증권 · 교보라이프플래닛 · SBI저축은행 · SK증권 · 국민은행 스타뱅킹 · 부산은행

  • 우리투자증권: 본문 슬랙 배치 이력 및 매체 연동 현황 참고
